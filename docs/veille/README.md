# Journal de veille technologique

## Objectif

Suivre l'évolution des briques techniques du projet et de son cadre
réglementaire, pour anticiper les ruptures plutôt que les subir.

## Cadence

Une séance hebdomadaire d'environ une heure, le vendredi.
Chaque séance produit au moins une fiche datée dans ce dossier.

## Sources suivies

| Source | Objet | Fréquence |
|---|---|---|
| Pages de publication GitHub des briques du projet (SeaweedFS, Airflow, dbt, DuckDB, Redpanda) | versions, failles, abandons | hebdomadaire |
| Blog technique Apache Airflow | orchestration | mensuel |
| dbt Developer Blog | transformation | mensuel |
| Data Engineering Weekly (infolettre) | panorama du domaine | hebdomadaire |
| CNIL — actualités | RGPD, données personnelles | mensuel |
| ANSSI — bulletins d'actualité | sécurité | hebdomadaire |

## Format d'une fiche

Nom du fichier : `AAAA-MM-JJ-sujet-en-minuscules.md`

Sections : source · constat · analyse · impact sur le projet · décision ou action.

Une fiche ne résume pas un article : elle conclut. Si elle ne débouche sur
aucun impact ni aucune action, elle n'a pas sa place ici.
